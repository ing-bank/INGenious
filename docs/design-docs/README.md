# Design Docs Index

One design/requirement doc per notable change in this repo, following the
shared INGenious design-doc template (see `p33148-ingenious-dev-tools`
`design-doc-tooling/templates/design-doc-template.md`).

## Adding a doc

1. Copy `design-doc-template.md` into this folder as `<DocID>-<slug>.md`
   (e.g. `DD-ENG-2026-015-matomo-project-profile.md`).
2. Fill in the front matter and sections.
3. Regenerate this index:
   ```
   python3 design-doc-tooling/scripts/generate_doc_index.py --root docs/design-docs
   ```
   (No script handy? Just add a row to the table below by hand, copying
   the values straight from the doc's front matter — see the columns.)

## Status field reference

| `status` | Meaning |
|---|---|
| `Draft` | Still being written, not yet shared for review |
| `In Review` | Shared for feedback | 
| `Approved` | Reviewed and accepted (independent of whether the code has shipped yet) |
| `Superseded` | A replacement doc exists **and** that replacement has actually released |
| `Deprecated` | Abandoned, with no replacement doc |

| `release_status` | Meaning |
|---|---|
| `not_started` | No code yet |
| `in_dev_branch` | Code lives in an individual dev branch — reviewed/QA'd, not yet PR'd further |
| `in_feature_branch` | Merged into a feature-accumulator branch; feature still accumulating |
| `in_release_branch` | Merged into the release-accumulator branch; not yet promoted to `main` |
| `released` | Release branch promoted to `main`, or a hotfix merged straight to `main` |

See `design-doc-tooling/README.md` for the full git-flow model these map to,
and the manual/scripted ways to keep this index and the release fields
up to date.
